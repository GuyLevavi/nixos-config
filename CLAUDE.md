# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```fish
rb              # cd /etc/nixos && git add -A && sudo nixos-rebuild switch --flake /etc/nixos#(hostname)
update          # nix flake update && rb
hyprctl reload  # apply hypr/*.conf changes without logging out or rebuilding
```

```bash
# Debug a failed rebuild:
sudo nixos-rebuild switch --flake /etc/nixos#gpubox --show-trace

# Roll back:
sudo nixos-rebuild switch --rollback

# List generations:
sudo nix-env --list-generations --profile /nix/var/nix/profiles/system
```

## Architecture

```
flake.nix                       # entry point — nixpkgs (unstable), home-manager, noctalia
hosts/
  cpubox/default.nix            # Intel laptop, integrated graphics only
  gpubox/default.nix            # + nvidia.nix (PRIME sync), Steam, gamemode
  */hardware-configuration.nix  # generated by nixos-generate-config; do not edit by hand
modules/
  core.nix                      # boot, nix settings, locale, user (bash login shell)
  desktop.nix                   # hyprland+uwsm, greetd, pipewire, fonts, podman, gnome-keyring, noctalia (system)
  laptop.nix                    # power, lid, bluetooth, touchpad, firmware — shared, both hosts are laptops
home/
  default.nix                   # ownership rule (Noctalia vs Nix), out-of-store symlinks for hypr/
  noctalia.nix                  # the shell (user service)
  shell.nix                     # bash->fish exec, starship/zoxide/atuin/fzf, delta/lazygit/gh
  tmux.nix                      # tmux (plugin-less, Noctalia palette) + workmux pkg/config
  skills.nix                    # mattpocock/skills, discovered from the flake input
  programs.nix                  # terminal, core CLI (ripgrep/bat/eza/fd/...), media tools
  zed.nix                       # Zed editor (LSPs, Tokyo Night via extension, format-on-save)
  apps.nix                      # obsidian + rclone Google Drive bisync, spotify
  scripts.nix                   # rb / update / screen-record
hypr/
  hyprland.conf, binds.conf                  # edited live, NOT in the nix store
```

**Machines:** `cpubox` (Intel laptop, integrated graphics) · `gpubox` (RTX 4060 laptop, PRIME sync, Steam).

Full design rationale (ownership rules, ordering, gotchas) is in `README.md` — read it before making structural changes.

## Critical Patterns

### Desktop: Hyprland + Noctalia

`programs.hyprland.enable = true` (with `withUWSM = true`) + `programs.noctalia.enable = true` + `services.greetd` in `modules/desktop.nix`. The Noctalia **user** service is enabled in `home/noctalia.nix` (`systemd.enable = true`), not the system one — do not flip both on.
**Desktop geometry is one constant: 8px.** `gaps_out = 8` with `gaps_in = 4` (Hyprland's `gaps_in` is a half-gap) in `hypr/hyprland.conf`, matched on the bar by `margin_edge` / `padding` / `widget_spacing = 8` with `margin_ends = 0`. Islands then sit 8 from the screen edges, 8 apart, and 8 above the windows — the last is free, since the exclusive zone ends at the bar and `gaps_out` supplies the gap. **These are one setting in two files:** changing `gaps_out` without changing the three bar keys drifts the islands off the window grid. `margin_ends` and `padding` **stack**, so `margin_ends` must stay 0. Radii follow the concentric rule (`outer = inner + gap`): windows and islands `8`, workspace pills `capsule_radius = 2` (8 − 6 group padding), screen corners `16` (8 + 8).

**Noctalia cannot match Hyprland's window shadows.** `bar.default.shadow = true` grows the layer surface but draws _nothing_ under the islands — it only hazes the top 6px of the windows beneath, since the bar is `layer = "top"`. `contact_shadow` is a no-op. Both stay off. Note the window shadow ramps ~5px, so a bar-to-window gap below ~8 gets visually swallowed (measured 75% of wallpaper brightness at 4px, 97% at 8); if `gaps_out` ever drops, `margin_opposite_edge` adds to the exclusive zone without moving the bar surface and is the lever to compensate.

**Idle is Noctalia's, not hypridle's.** `[idle.behavior.*]` in `home/noctalia.nix` (actions `lock` / `screen_off` / `suspend` / `lock_and_suspend` / a custom `command`, each with `timeout` and an optional shorter `locked_timeout` that applies only once locked). hypridle was dropped because every action it invoked was already a Noctalia one, so it was only a timer around this — and one that could deadlock: hypridle subscribes to logind's `Lock` signal and `loginctl lock-session` emits it, so a `lock_cmd = loginctl lock-session` self-triggered at a measured 3110 forks/sec. In-process there is no round trip to re-enter. `pre_action_fade_seconds` is global, not per-behavior, so a custom brightness-dim behavior would draw the fullscreen fade over itself — that is why the old 150s `brightnessctl` dim listener became the fade rather than being ported. Lock-before-suspend needs no config: Noctalia takes a logind sleep-delay inhibit on `PrepareForSleep` and locks first, covering lid close and `systemctl suspend`.

**No idle suspend, on purpose.** The `suspend` behavior is declared with `enabled = false` so the choice stays visible: the machine is left running unattended so a phone can reach sessions on it, and suspending kills that where locking does not. logind's `HandleLidSwitch = "suspend"` (`modules/laptop.nix`) is the battery backstop — off AC only, since `HandleLidSwitchExternalPower = "ignore"`.

**Bar lane anchoring decides which islands jitter.** `start` is left-anchored and grows rightward, so anything placed after `group:left` gets shoved every time the active-window title changes length; `end` is right-anchored, so an island at its head keeps a fixed right edge. That is why `media` lives at the head of `end` (right of the centre clock) rather than second-from-left.

`hypr/hyprland.conf` and `hypr/binds.conf` are symlinked out-of-store from `/etc/nixos/hypr/` (see `home/default.nix`) — edit them directly and run `hyprctl reload`, no rebuild needed. This is the only part of the repo that works this way. Two sourced files are runtime-written, not in the repo: `~/.config/hypr/noctalia.conf` (theme colours) and `~/.config/hypr/monitor-state.conf` (monitor-watch's eDP-1 disable).

### Theming: Noctalia owns it, not Nix

Switching the palette in Noctalia's bar/settings writes GTK/Qt/ghostty/helix/Firefox theme files at runtime (`SUPER+T` just opens the Noctalia settings window). btop is split: Noctalia owns `~/.config/btop/themes/noctalia.theme`, but `btop.conf` is Nix-owned (`programs.btop`, `home/programs.nix`) with `color_theme = "noctalia"` preset so Noctalia's hook never rewrites it. `gtk.enable`/`qt.enable` are `false` on purpose — home-manager must never write those same files as read-only store symlinks. Do not add Stylix. `programs.noctalia.settings` in `home/noctalia.nix` seeds `config.toml` (theme + template ids); the GUI's `~/.local/state/noctalia/settings.toml` still overrides per-key at runtime. See `README.md` "Who owns what" before changing this.
Zed has no Noctalia template, so the palette reaches it by hook: `colors_changed` / `theme_mode_changed` / `started` in `home/noctalia.nix` run `noctalia-zed-theme`, which rewrites the `theme` block of `~/.config/zed/settings.json` (mutable; Zed live-reloads the file, so switches apply without a restart). The map is theme-name granularity — `Catppuccin` → `Catppuccin Mocha`/`Latte` (the default palette), `Tokyo-Night` → `Tokyo Night`, Gruvbox/Ayu ship with Zed, the rest (kanagawa, rose-pine, nord, dracula, eldritch) come from the registry extensions listed in `home/zed.nix`; non-builtin palettes keep the Catppuccin fallback. Since activation re-seeds that block from Nix (Nix wins the deep-merge), a `home.activation` entry re-runs the sync right after `zedSettingsActivation` so the runtime palette survives `rb`. The ownership rule only applies to files Noctalia actually rewrites — this one file is deliberately co-owned: Nix seeds, the hook owns at runtime. tmux is synced the same way (`noctalia-tmux-theme` parses the ghostty theme Noctalia writes — palette 0-15 — and rewrites the out-of-store `~/.config/tmux/palette.conf`, which `home/tmux.nix` sources; the ANSI block there is only a fallback before the first sync). workmux's global config and OpenCode status plugin are Nix-owned in `home/tmux.nix` from the pinned `workmux` input; `status_format` is off so that file's `window-status-format`, which embeds `@workmux_status`, owns the bar.

### Shell: bash (login) + fish (interactive)

`users.users.${username}.shell = pkgs.bash` in `modules/core.nix` — bash stays the process/login shell so scripts, `sudo -s`, systemd, etc. all keep POSIX semantics. `home/shell.nix` has bash `exec` into fish on every _interactive_ start, guarded on the **parent process** (`ps -o comm= -p $PPID` != fish), not on an exported marker, AND on having a real terminal (`-t 0 && -t 1`). The marker this used to use was inherited by every descendant of the fish session, so anything spawning `$SHELL` from inside it — an editor's integrated terminal, a tmux pane — found it set and stayed in bare bash with no starship. Parent-is-fish is the only case that must not bounce back (you typed `bash` at a fish prompt and meant it). The tty test is for GUI tools: Zed captures its environment via `bash -l -i -c` with no terminal attached, and an unconditional exec replaces bash before the `-c` command runs — fish reads stdin instead, the capture finds no JSON, and every worktree loses its PATH (nixd "not available in your environment"). Non-interactive bash (`bash -c ...`) is excluded by the `$-` test as well as by never sourcing `.bashrc`.
starship/zoxide/atuin/fzf all have first-class fish support in home-manager (`enableFishIntegration`) — no hand-rolled init file needed, unlike the xonsh setup this replaced.

### Editors: Zed

`home/zed.nix` is the only editor config: VSCode keymap, format-on-save, LSPs via `extraPackages` (basedpyright/ruff/nixd, clang-tools for C, markdown-oxide for Obsidian-style markdown — extensions resolve those binaries from PATH first, so the nix builds are what run), `defaultEditor = true` so `EDITOR`/`VISUAL` are `zeditor -w` (helix stays in `home/programs.nix` as the zero-config terminal fallback). UI: every panel docks right (`project_panel`/`git_panel`/`outline_panel`/`collaboration_panel`/`agent` — upstream `agent` defaults left), status-bar buttons off, `ctrl-b` is remapped to `workspace::ToggleRightDock` because there is no left dock for the stock `workspace::ToggleLeftDock` to open (panel `ToggleFocus` actions only move focus, they never close a panel), and `ctrl-alt-m` is an extra agent toggle next to the stock `ctrl-?`/`ctrl-alt-i`. Extensions are registry ids — home-manager turns them into `auto_install_extensions` and Zed downloads them at runtime, so a newly added extension needs network on first launch, and a _removed_ one is never uninstalled (delete it from Zed's Extensions panel). With `mutableUserSettings = true` activation deep-merges Nix over the live `settings.json` (Nix wins per key, and keys dropped here linger there until deleted by hand). Sign-in is NOT in settings.json — credentials live in gnome-keyring via org.freedesktop.secrets (`modules/desktop.nix`), so Nix ownership never signs you out; without the keyring daemon a sign-in lasts only until Zed exits.

## Notes

- `system.stateVersion` and `home.stateVersion` are `"25.05"` — **do not change**
- Both `cpubox` and `gpubox` import `modules/laptop.nix` — both machines are laptops (lid switch, battery, touchpad, bluetooth all apply)
- `gpubox` uses PRIME **sync**, not offload: the dGPU is always on (Steam/gamemode need the sustained perf); no `nvidia-offload` wrapper needed, but no idle power-down either
- `programs.claude-code` has no home-manager module — add via `home.packages` (`home/programs.nix`)
- Podman is enabled system-wide in `modules/desktop.nix` (`dockerCompat = true`) — activate the socket per-session with `systemctl --user enable --now podman.socket`
- `home/apps.nix`'s rclone Google Drive sync needs a one-time manual `rclone config` (remote name `gdrive`) and a `--resync` first run — can't be declared in Nix, see the comment in that file. The unit is guarded by `ConditionPathExists` on `rclone.conf`, so until that is done it is _skipped_, not failed; `systemctl --user list-timers` still shows it armed
- `services.openssh` is **off on purpose** (`modules/core.nix`) — it was open on port 22 with no `authorizedKeys` anywhere. Only ever re-enable it in the same commit that adds a key
- `zramSwap` is on for both hosts: `gpubox` has `swapDevices = [ ]` and would otherwise OOM-kill rather than stall under Steam
- The only port this config opens is **UDP 5353** (avahi/mDNS, for driverless printer discovery via `services.printing`)
- k9s/helm, direnv, and kanshi (multi-monitor auto-profiles) were considered during the 2026-08 rehaul and deliberately left out — add them back the same way as everything else here if that changes
